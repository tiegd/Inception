# User documentation

This document explains how to use the Inception stack as an end user or administrator. For installation and development, see [DEV_DOC.md](DEV_DOC.md).

All commands below are run from the root of the repository.

## 1. Services provided

The stack hosts a WordPress website, served over HTTPS.

| Service | What it does for you |
|---|---|
| **nginx** | The only public entry point. Serves the website over HTTPS (port 443) |
| **WordPress (PHP-FPM)** | The website and its administration panel |
| **MariaDB** | The database that stores the articles, comments and user accounts |

You only ever talk to nginx: the website and the administration panel are both reached through `https://gaducurt.42.fr`.

## 2. Start and stop the project

| I want to... | Command |
|---|---|
| Start everything (builds the images on the first run) | `make` |
| Pause the services, keeping the containers | `make stop` |
| Resume paused services | `make start` |
| Stop and remove the containers (**data is kept**) | `make down` |
| Restart from fresh containers (**data is kept**) | `make restart` |
| Erase **everything**, including the website content | `make fclean` |

Notes:

- The first `make` takes a while: the images are built and WordPress is downloaded and installed. Follow the progress with `make logs` (press `Ctrl+C` to leave the logs).
- After a reboot of the machine, the services restart by themselves, unless you had stopped them manually before.
- `make fclean` is irreversible: it deletes the database and all the website files (articles, comments, uploaded images).

## 3. Access the website and the administration panel

1. Make sure the machine that runs your browser resolves the domain name. This line must be present in `/etc/hosts`:

   ```
   127.0.0.1 gaducurt.42.fr
   ```

2. Open the website: **https://gaducurt.42.fr**
3. Open the administration panel: **https://gaducurt.42.fr/wp-admin**

Your browser shows a security warning, because the HTTPS certificate is **self-signed** (generated by the project, not by a public authority). This is expected: choose "Advanced", then "Accept the risk and continue".

Two accounts exist:

| Account | Role | What it can do |
|---|---|---|
| Administrator | `administrator` | Manage the whole site: posts, comments, users, settings |
| Second user | `author` | Write and publish their own posts |

The user names are defined in `srcs/.env` (`WP_ADMIN_USER` and `WP_USER`).

## 4. Locate and manage credentials

Credentials are stored locally, in files that are **not** part of the Git repository.

| What | Where |
|---|---|
| Passwords of the WordPress accounts (administrator and author) | `secrets/credentials.txt` (lines `WP_ADMIN_PASSWORD=` and `WP_USER_PASSWORD=`) |
| Password of the database user used by WordPress | `secrets/db_password.txt` |
| Password of the database `root` user | `secrets/db_root_password.txt` |
| User names, e-mails, domain name, database name | `srcs/.env` |

Good practice:

- never share these files and never commit them to Git;
- keep them readable only by you: `chmod 600 secrets/*.txt`.

## 5. Check that the services are running correctly

**1. State of the containers**

```bash
make ps
```

Expected: `mariadb`, `wordpress` and `nginx` are all `Up`, and `mariadb` shows `(healthy)`. Only `nginx` shows a published port (`0.0.0.0:443->443/tcp`).

**2. The website answers**

```bash
curl -kI https://gaducurt.42.fr
```

Expected: an HTTP status line, such as `HTTP/1.1 200 OK`, or a redirection (`301` or `302`).

**3. Open the site in a browser.** The WordPress home page must display. Log in at `/wp-admin` with the administrator account.

**4. The two accounts exist**

```bash
docker exec wordpress wp user list --path=/var/www/html --allow-root
```

Expected: one `administrator` and one `author`.

**5. Look at the logs if something is wrong**

```bash
docker logs --tail 20 nginx
docker logs --tail 20 wordpress
docker logs --tail 20 mariadb
```
